# LadyM v0.10.0

**Evidence-backed memory, bounded maintenance, and reversible embedding migrations**

LadyM v0.10.0 extends the existing local-first memory engine with traceable claims,
source-aware invalidation, deterministic knowledge navigation and budgeted
background maintenance. It also hardens retrieval, concurrent initialization,
cross-process consistency and model migration.

The architecture remains a modular Go application with a shared Engine,
SQLite/PostgreSQL storage, zero-cgo production binaries and no new external
database, queue or service requirement.

The `v0.9.0` tag was reserved during validation but was not published as a GitHub
Release. The tag is retained unchanged. This release uses the next available
minor version and includes a portable Git-fixture fix found by the Linux gate.

## Highlights

- **Traceable knowledge:** attach evidence, scopes, fingerprints and revisions
  to claims; verify, correct or reject them through explicit feedback.
- **Freshness by construction:** invalidate dependent knowledge when its sources
  change, expire, retire or are deleted.
- **Source-grounded navigation:** build explicit topic views, combine lexical,
  vector and structural retrieval, and bound injected context.
- **Controlled background work:** persist and deduplicate jobs with leases,
  cancellation, atomic checkpoints and measurable budgets.
- **Recoverable model changes:** identify vector spaces explicitly and migrate
  through staging, atomic activation, rollback and finalization.

## Added

### Evidence, claims and archival

- Typed evidence references with SHA256 content fingerprints and Unicode-safe
  excerpt ranges.
- Claims with inferred/user-asserted initial state, caller-attested verification,
  correction, rejection, environment/code-version conditions and expiration.
- Expected-revision compare-and-swap and source snapshot guards for feedback.
- Opt-in archival with best-effort credential redaction, a 64 KiB entry limit,
  an 8 MiB persisted-text limit per workspace and configurable retention.
- Workspace-isolated HTTP, MCP, CLI and Go/Python/TypeScript SDK operations.
  HTTP actor attribution comes from authentication, not request-body assertions.

### Topics, hybrid recall and bootstrap context

- Deterministic topic views of explicitly selected sources, with complete source
  IDs, fingerprints, revisions and a 16 KiB view limit.
- Hybrid lexical, vector and bounded graph retrieval with deterministic ranking.
  Exact symbols and paths can be found without embeddings.
- Reference-only bootstrap context: at most 4096 UTF-8 bytes remotely; embedded
  Go/LangGraph hosts can supply a local tokenizer for exact token budgets.
- Explicit task state with expiration. Predictions are not converted into
  user-authorized goals.

### Persistent maintenance

- Allowlisted `new_episode`, `refresh_topic` and `expire_claim` jobs with stable
  identities, deduplication, durable arguments and input revisions.
- Owner-token leases, takeover after a crash, bounded attempts and transaction-time
  publication fences. Expired, cancelled or superseded workers cannot publish.
- Atomic output/provenance/checkpoint commits and stored-embedding reuse.
- Opt-in budgets for candidate count, provider calls, reserved bytes, wall time
  and concurrency; low-cardinality metrics and persisted reports.
- Context propagation through supported providers, PostgreSQL transactions and
  SQLite writer waits. Unsupported uncancellable providers are rejected in
  budgeted mode rather than hidden behind background goroutines.

### Embedding migration and capture identity

- Provider/model/dimension/tokenizer fingerprints, including detection of
  different models with the same vector dimension.
- Durable ordered staging, generation fences, atomic activation, retained
  rollback vectors and explicit finalization.
- Local `ladym migrate embeddings` status/adopt/resume/rollback/finalize commands.
- Opt-in canonical Git-root/workspace and path-resource identities. Structural
  paths do not participate in fuzzy alias merging or embedding migration.

## Changed

- Retrieval filters workspace, type, status and system-item eligibility before
  top-k selection. SQLite's lazy vector index observes external committed changes.
- Deep retrieval re-evaluates heuristic sufficiency instead of always reporting
  success, and graph expansion has an explicit candidate budget.
- Consolidation and derived-model/playbook publication are atomic with source
  guards and provenance. Offline similarity alone no longer authorizes overwrite.
- Automatic decay protects referenced evidence. Explicit deletion synchronously
  invalidates descendants, including through stale intermediate nodes.
- Public managed-memory reads suppress stale bodies and check transitive expiry.
  Internal Store access remains a privileged raw audit interface.
- Hook success is an observed tool outcome, not proof of task correctness.
  LangGraph-retained Q/A is episodic and observed.
- L5/L6 progress is workspace-specific; timestamp/ID cursors avoid skipped
  episodes with equal timestamps.
- Retrieval evaluation keeps legacy metrics and adds source-slot evidence metrics.
  Live LLM evaluation now requires an explicit model, question limit and budget.

## Fixed

- **Fresh-database concurrent startup:** API and worker initialization could mix
  stale dimension metadata with a newly published fingerprint. Initialization
  now checks identity and vectors in the existing storage transaction, accepts
  a matching concurrent initializer and rejects unidentified legacy vectors.
  No restart policy, startup-order workaround or relaxed fingerprint check is used.
- **Cancellation and working memory:** PostgreSQL contextual `BeginTx` paths now
  inherit deadlines, and contextual Engine views share the correct L0 buffers.
- **Migration recovery:** immutable per-provider tokenizer identity, fenced
  automatic finalization and persisted resume intent prevent cross-generation
  corruption or accidental loss of an explicit rollback window.
- **Identity and freshness edges:** canonical path separation, distinct topic/task
  IDs, freshness checks on code-file fallback and memoized provenance traversal.
- **Provenance and clients:** retain missing source IDs after graph-edge deletion;
  preserve multi-source mappings and normalize nullable Python claim conditions.
- **Evaluation deadlines:** live answer calls use a bounded, reaped subprocess so
  a trickling response cannot defeat the total wall budget.
- **Portable release validation:** canonical identity tests create real
  non-repository fixtures rather than invalid Git-directory sentinels. The
  release workflow can also run its test gate manually before a tag is created.

## Compatibility and upgrade guidance

> Back up the entire database before upgrading, adopting an identity or migrating
> embeddings. Preserve SQLite WAL consistency or use the deployment's PostgreSQL
> backup procedure.

1. **Existing vector stores:** unidentified legacy vectors are not silently
   assigned to a model. Use explicit identity adoption only when you can attest
   their provenance; otherwise migrate them.
2. **Rollback window:** content, vector and structural/trust metadata writes are
   frozen until finalization or rollback. Touch/accounting remains permitted.
   Explicit deletion remains synchronous and cannot be undone by vector rollback.
3. **Custom Store implementations:** the `storage.Store` interface has new
   consistency, mutation, migration and context methods; update custom adapters.
4. **Injected providers:** existing unidentified vectors require a meaningful
   provider identity. Budgeted work requires supported cancellable provider
   interfaces with raw-output accounting.
5. **Deliberate behavior changes:** offline consolidation is conservative;
   deep recall may honestly remain insufficient; retained Q/A is not a semantic
   fact; system jobs and predictions do not displace ordinary knowledge.
6. **Downgrade:** do not assume older binaries understand system-record isolation
   or migration state. Follow the export/cleanup and recovery guidance before
   using a release without these contracts.

Defaults remain conservative: archive and budgeted maintenance are disabled,
capture identity remains `legacy`, and topics are explicitly built. No automatic
historical transcript import, autonomous verifier, command executor or UI
redesign is introduced.

## Trust and operational limitations

- Verification is **caller-attested**. LadyM does not independently execute tests
  or certify model-generated claims.
- Redaction is best-effort credential masking, not a complete PII/secrets detector
  or a retroactive sanitizer for existing hook history.
- Worker reservation and measured units are **bytes**; provider output-token caps
  are separate. These are not billing-token or cost-savings claims.
- PostgreSQL conservatively serializes memory mutations for correctness.
  Concurrent-write throughput has not been benchmarked.
- Offline fixtures measure source coverage, stale use, timing and context size.
  Hosted-model QA uplift, production latency and token savings were not measured.

## Verification

- Complete personal and enterprise suites against real PostgreSQL, plus SQLite
  coverage in the personal edition.
- Race checks, explicit migration/recovery/cancellation regressions, and English
  Go comment lint.
- Python and TypeScript SDK tests, including real loopback server integrations.
- Offline benchmark and live-answer deadline regressions.
- **Ten consecutive fresh-volume Docker Compose starts** of the final cold-start
  fix: API and worker started concurrently, with no restarts; health checks,
  persisted metadata and remember/recall round trips passed.
- Release automation gates tests, builds all platform/edition archives and
  publishes `SHA256SUMS`.

The release workflow provides Linux and macOS archives for amd64 and arm64:

| Variant | Contents |
|---|---|
| `ladym-personal-*` | SQLite/PostgreSQL CLI and embedded console |
| `ladym-personal-fulldict-*` | Personal edition with embedded CJK dictionary |
| `ladym-enterprise-*` | PostgreSQL-only `ladym` and separate `ladymconsole` |

Verify archive integrity against the attached `SHA256SUMS`. From source:

```sh
go install github.com/ProjAnvil/LadyM/cmd/ladym@v0.10.0
ladym doctor
```
