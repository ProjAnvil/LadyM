### 教训（第 3 次踩）
- macOS BSD grep 不支持 `\|` 转义（BRE 下视为字面量），用 `grep "a\|b"` 会静默返回空并误判「不存在」。本轮又踩两次（查 go.mod 的 tiktoken、查 tokenizer.go 顶层声明），误以为依赖不存在。**铁律：用 Grep 工具，不用 bash grep。**
- **bash 双引号里的反引号会做命令替换**：`git commit -m "...\`ladym\`..."` 导致 shell 去执行 ladym、命令挂死（exit 137/SIGTERM）。长提交信息改用 `git commit -F 文件`。

### 评测方法论教训（通用，价值高）
- **复制文件后立刻 spawn，文件还在页缓存里 → 根本测不到「冷」**。我曾误加 cold/warm 拆分并据此写 README，被独立审查抓出。数据其实早报警（cold 31.4 vs warm 29.9 几乎无差）但我没读出来。
- **不做预热就平均，首调会虚高 20 倍**（实测 753ms vs 39ms），因为首次调用含建库与冷页缓存。
- **同一 payload 重复多次取 token 百分位 = p50==p95==p99**，token 样本必须每 trial 只取一次。

### 性能瓶颈根因已定位（供下轮修复，勿重复调研）
- **引擎打开 O(n) 的根因**：`storage/store_sqlite.go:198-200` 的 `NewStore` 无条件调 `warmIndexFromBlobs()`，该函数 `SELECT id, embedding FROM memories WHERE embedding IS NOT NULL` 全表扫描并逐行 decodeVec + Upsert 进内存向量索引，**每个进程启动都做一次**。这就是 0.6→2.1→15.2ms 的来源。
- **resolve 随规模增长**（0.039→1.348ms）是内存向量索引的线性扫描（n × dim=256）。
- **中文切词**在 `storage/embeddings.go:36 segmentCJK`，约 0.1ms/字。
- 候选优化方向：索引懒加载 / 持久化索引 / 只按需加载；CJK 切词结果缓存或绕过（hashing embedding 未必需要词典切词）。
