# 2026-10-20

## 调研：ai-memory（akitaonrails/ai-memory）对比 LadyM

- 报告：`docs/research/2026-10-20-ai-memory-vs-ladym.md`
- 核心结论：方向不同——ai-memory 解「agent 间交接协作」（工程化共享工作台：git 版本化 Markdown 真相源 + claim-once handoff + hooks 静默捕获 + 默认零 LLM）；LadyM 解「单个 agent 记忆认知过程」（L0-L6 认知架构 + 代码 RAG 融合）。
- LadyM 优势：代码 RAG（对方完全没有）、recall_ops 结构化操作历史、ACT-R 激活与两档检索、测试纪律、ADD/UPDATE/DELETE/NOOP 整合原语。
- 最大差距：静默捕获——对方用 lifecycle hooks 零配合喂料 + 类型化脱敏；LadyM 全靠 agent 主动调用，无料则认知管线空转。其次：handoff 原语、人类可读真相源（Markdown+git）、团队运维、生态成熟度（对方 11.5k stars）。
- 建议优先级：hooks 自动捕获通道 > handoff 原语（L1 type=handoff）> SQLite→Markdown git 投影导出层。
- 对方成熟度数据：Rust 单二进制，11.5k stars / 819 forks / 4115 commits，MIT。

## 调研：hook 触发载体选型（Go vs Python）

- 报告：`docs/research/2026-10-20-hook-carrier-selection.md`
- 结论：Go，做 `ladym hook` 子命令（读 stdin JSON 按 hook_event_name 分派，exit 0 静默观察者，不做 decision/block）。
- 关键事实：Codex 2026 年起内置 Claude-style lifecycle hooks（hooks.json/config.toml [hooks]，事件名/matcher/stdin JSON/exit code 与 Claude Code 几乎同构），一套子命令服务两家；差异：Codex 有 trust-review（/hooks，hash 绑定）、notify 通道是 argv 传 JSON（非 stdin，仅 agent-turn-complete）。
- Claude Code 另有 `type: "http"` hook，可直连 `ladym serve --http` 数据面，作可选第三路径。
- command 字符串写 `ladym hook`（无 shell 语法）天然跨 bash/powershell。
- 事件映射初稿：SessionStart/End→episode 边界；UserPromptSubmit→prompt episode；Pre/PostToolUse→action_class 按工具名映射受控词表，tool_input 文件路径喂 resources 槽走 operates_on 确定性建边。
- 设计要点：脱敏边界（ignore_paths/allowlist + 密钥打码）第一版就要有；直写 SQLite（WAL），spool 削峰等实测瓶颈再上；Windows 双执行路径（Git Bash/powershell）要补测试。
- 下一步：用户确认后写规格（ladym hook 子命令 + 事件映射器 + 两家 plugin/配置生成器）。

## 规格：hook 静默捕获与 plugin market（个人版）

- 规格文档：`docs/superpowers/specs/2026-10-20-hook-capture-plugin-market-design.md`（待用户确认）
- 用户决策（AskUserQuestion 确认）：workspace=cwd 目录名；V1 核心五类事件（SessionStart/End、UserPromptSubmit、PostToolUse、Stop + Claude 独有 PostToolUseFailure）；分发两方向=个人版 CLI 安装器 + plugin market；**脱敏 V1 不做**（显式取舍）。
- 关键澄清：**企业版不做 hook**——企业版本质是 memory 数据库，捕获是客户端职责（个人版 CLI/plugin）。
- 技术接入点：新包 `hook/`（对齐 code/ 先例，纯函数解析+映射）+ cli 加 hookCmd；写入走 `engine.RecordOperation(OperationEvent)`（ActionClass 直填受控词表、Resources 从 tool_input.file_path 取文件名、harness 名进 Agent、session_id/transcript_path 进 Metadata）。
- install 语义：合并不覆盖（幂等，command 为 `ladym hook` 的条目识别自己人）、写前备份 `.ladym-bak`、Codex 装完提示 /hooks trust。
- 里程碑 M0-M4：hook 包 → 子命令 → install/uninstall → plugin market（plugins/ladym 目录 + marketplace，Codex manifest schema 待核对）→ 文档。
- 代码事实（回答 db 定址时核实）：`config.defaultDBPath()` 默认 = LADYM_DB 环境变量，否则**进程 cwd 下的 ladym.db**（项目级隔离，每个项目一个库）。hook 进程由 harness 启动、cwd 继承项目根 → 零配置默认就是每项目一个 db；设 LADYM_DB 走统一库，此时 workspace=cwd 目录名成为隔离键。db/workspace 都是每次 hook 进程启动时运行时解析，安装时只写裸 command `ladym hook`。

## 实施开始（分支 feat/hook-capture-plugin-market）

- 计划：`docs/superpowers/plans/2026-10-20-hook-capture-plugin-market.md`（任务 1-12，M0-M4）。基线 21 包全绿。规格偏差修订：command 带 `--harness`（stdin 两家同构无法自动判别来源）。
- M3 官方规范核对（已完成）：
  - **Codex plugin**：唯一必须文件 `.codex-plugin/plugin.json`（只有它放该目录内，其余都在 plugin 根）；字段 name（kebab-case 必须）/version（semver 必须）/description（必须）+ author/homepage/repository/license/skills/mcpServers/hooks/apps/interface{displayName,shortDescription≤125,...}；hooks 默认路径 `./hooks/hooks.json` 可省 manifest 字段；`.mcp.json` 支持 MCP server 分发；安装 `/plugins` 或 `codex plugins install ./path`；官方 hooks 文档（2026-10）确认 plugin 捆绑 hooks 会加载并走 trust-review。
  - **Claude Code plugin**：`.claude-plugin/plugin.json`，name 唯一必填（kebab-case，禁 claude-/anthropic- 前缀），version/description/author/license 可选；hooks 默认 `hooks/hooks.json`（文件内必须有顶层 "hooks" 包装键，与 settings.json 内联形状不同）；`${CLAUDE_PLUGIN_ROOT}` 占位符指向已安装 plugin 绝对路径（我们不用——command 指向 PATH 的 ladym）。
  - **Claude marketplace**：`<root>/.claude-plugin/marketplace.json`，必填 name/owner{name}/plugins[{name(须与 plugin.json name 一致), source, description}]；source 相对路径（禁 `..`）或 github/git-subdir 对象；验证 `claude plugin validate`；官方名称 claude-plugins-official 保留。
  - **结构决定**：两家 manifest 文件名不同（.claude-plugin/ vs .codex-plugin/），但 hooks 事件集有差异（PostToolUseFailure 仅 Claude）→ 分两个 plugin 目录：plugins/ladym（Claude）+ plugins/ladym-codex（Codex），plugins/ 根放 marketplace.json。
